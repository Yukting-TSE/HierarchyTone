# HierarchyTone 实验原型重构与流程规范

> 状态：方案稿（先不定稿代码）  
> 范围：实验二读屏原型 + 现场实验流程；实验一听觉导航原则上不动，只接入统一会话壳  
> 约束：盲校现场、可离线、浏览器打开即可、主试一人可带测

---

## 1. 要解决什么

现有 `prototype/实验二.html` 是**演示页**，不是实验系统。它能展示「音高 = 层级」的概念，但不能按论文口径稳定收数据。

核心缺口有三类：

1. **刺激面太小**：中间是 375px 手机框。低视力被试会凑近、放大、用残余视力「看」，视线和指针很容易滑出手机模拟区，落到左右研究面板上。问题在框太小，不在「用悬停模拟指读」。
2. **悬停实现不稳，但隐喻是对的**：`mouseover` 对应手机读屏的「触摸浏览 / 指哪读哪」（TalkBack Explore by Touch、VoiceOver 触探）。应保留为正式输入，不要改成记快捷键。要修的是父子嵌套抢焦点、滑出框外误触研究面板。
3. **没有实验流程**：无被试编号、无练习/正式任务、无条件对照、无超时、无结构化日志、无口头问卷录入。现在只是试用+访谈，和实验一的可重复性不匹配。

因此这次重构做两件事：

- **补一块足够大的探索面**（网页全幅，或把手机内容放大到几乎占满窗口），让指读不会扫出刺激区。
- **把实验二做成可上场系统**（任务、条件、记录、导出）。手机外壳不是自变量，见第 4.5 节：可以留、可以放大、也可以去掉，但不要做成每人两套正式题。

## 2. 现有资产：保留什么、丢掉什么

### 2.1 保留（直接迁到共享音频层）

| 资产 | 位置 | 用途 |
|------|------|------|
| 六级音高映射 | L1 C5 523Hz → L6 B2 123Hz | 自变量操作定义，论文口径不要改 |
| 提示音包络 | 200ms sine + 少量谐波，attack 15ms | 听感已调过，现场耳机可用 |
| 提示音 → 100ms → 语音 | `DUR + DLY` | 先结构后内容 |
| 购物 / 新闻两套内容 | 淘宝首页、头条首页 | 场景熟悉，继续当任务材料 |
| 元素标注 | `data-lv` / `data-sp` / `data-t` | 可迁成无障碍树节点 |

### 2.2 降级为「演示模式」，不再当正式试次

- 三栏布局（映射表、手机框旁边的研究面板、统计）
- 导出 wav、波形可视化、实时柱状图、层级色标（被试模式必须关掉）

悬停浏览**不是演示专用**，正式试次也用。演示模式仍要留：给老师、答辩、讲解音高原理。正式被试**默认进实验模式**（全屏刺激 + 悬停指读）。

### 2.3 实验一不动逻辑

`prototype/实验一.html` 的条件、路径、NASA-TLX、CSV 字段保持。只在外层加统一会话壳：同一 `participant_id` 贯穿两天/两段实验。

## 3. 目标架构（一句话）

**一套音频引擎 + 一棵无障碍树 + 一种指读输入（悬停）+ 一块足够大的刺激面 + 一个主试控制的实验状态机。**

刺激面优先做网页全幅；手机外壳是否保留，见 4.5，不作为第二自变量。

```
会话壳 session.html
  ├─ 被试建档（编号、视力、读屏经验、惯用设备）
  ├─ 实验一（可外链现有页，带回 PID）
  └─ 实验二 HierarchyTone
        ├─ 共享：audio.js / a11y-tree.js / logger.js / protocol.js
        ├─ 输入：悬停指读（正式）+ 点击激活
        └─ 刺激面：网页全幅（主）／手机放大（可选，非人人必做）
```

现场仍然是静态文件，双击或本地 HTTP 即可，不依赖后端。

## 4. 必须改的交互原则

### 4.1 被试看到的只是刺激，看不到研究面板

正式试次进入**全屏刺激态**：

- 隐藏左侧映射、右侧统计、顶栏场景切换。
- 屏幕只留当前外壳（手机或网页）+ 极简状态（可用语音报，不必写在屏上）。
- 主试用快捷键呼出控制台（建议 `` ` `` 或 `Ctrl+E`），不占被试视觉中心。

低视力被试一旦能「看见」研究面板上的 L1/L2 色标，音高自变量就污染了。

### 4.2 主输入保持悬停指读，不要改成记键

笔记本电脑上的指针划过 = 手机读屏的「手指划过屏幕读出焦点」。这是已有技能，现场几乎零教学。改成 ↑↓ Tab H 是在教一套电脑读屏，和实验二要模拟的手机使用不是同一件事，记忆成本不合理。

| 动作 | 对应真实读屏 | 本原型 |
|------|----------------|--------|
| 手指/指针划过元素 | 触摸浏览 / Explore by Touch | `pointermove` 进入节点 → 音高 + 语音 |
| 双击 / 单击激活 | TalkBack 双击、VoiceOver 双击 | 单击当前焦点节点算「选中/完成」 |
| 打断播报 | 再摸下一项即打断 | 进入新节点或离开刺激区即 `cancel` |

主试键可以留（`Esc` 中止、`Ctrl+E` 呼出控制台），**不教给被试**。

仍须修悬停实现：

- 命中测试按无障碍树取**最深节点**（或明确的叶子优先），避免卡片和内部标题来回抢。
- 指针离开刺激区：停播，不要让左右面板变成可聚焦元素。
- 刺激区要足够大，低视力划着划着不会「划出手机」。
- 节流：同一节点不重复触发；离开再进入才重播。

### 4.3 父子嵌套：一次只聚焦一个节点

现在商品卡和内部图片、标题会抢 `mouseover`。改为：

- 无障碍树是扁平浏览列表（深度优先），每一刻只有一个 `focusedNodeId`。
- 播报格式：`[音高] + 「角色，名称」`，例如「按钮，购物车」「标题，嫦娥六号…」。
- 指针在卡片上时，焦点落在当前命中的那一层（图、标题、整卡），与触摸浏览「指到哪读哪」一致，不另做「进组」键。

### 4.4 要放大的是探索面，不是换一套操作

375px 边框是低视力划出界的直接原因。对策按优先级：

1. 正式试次去掉左右研究面板，刺激区占满窗口。  
2. 若仍用手机视觉：按窗口放大，周围纯暗底、不可点。  
3. 若放大后仍不够：用网页全幅承载同一套购物/新闻结构（主路径）。

### 4.5 能不能去掉手机外壳？对实验有没有影响？

**音高自变量测得出来。** HierarchyTone 问的是「层级能否用音高被感知、能否帮着找结构」。这个不依赖屏幕看起来像不像 iPhone。网页大界面同样能布置 L1–L6，同样能做 C0/C1 对照。

**会变的是生态效度，不是内部效度。**

| 做法 | 对论文的影响 | 现场 |
|------|----------------|------|
| 去掉手机框，只做网页 | 结论应写成「大屏/网页指读场景」，不要再声称验证了手机 App 读屏；购物/新闻可以还是那套内容，但布局密度、目标大小、一屏信息量都变了 | 最省事，低视力不易划出界 |
| 只留放大后的手机 | 结论仍能对「手机界面结构」说话；若放大很多，已接近平板，要在方法里写清「实验室放大呈现，非真实握持尺寸」 | 中等；部分低视力仍可能出界 |
| 两套都做正式题 | 外壳变成第二个因素（密度、面积与音高缠在一起），N 和时长都不够拆；分析很容易说不清 | 不建议 |

**建议：正式实验只保留一种刺激面。**  
盲校时间紧、低视力会「看」、原先痛点就是框太小 → **正式题用网页全幅 + 悬停指读**。手机视觉可留在演示模式，或练习 1 分钟「这就是缩小版」，不当正式条件。  
若导师/论文叙述必须紧扣「手机读屏原型」，则**不要做第二套网站信息架构**，而是把现有淘宝/头条页拉满窗口（去金属边框、去两侧面板），操作仍是悬停。这样去掉的是「小框」，不是「手机内容」。

### 4.6 网页全幅会不会让论文没亮点？

**不会伤主贡献。** 论文亮点不在「像不像 375px 手机」，而在三层贡献（见摘要）：

1. 理论：界面结构功能的区分性—预测性—可控性分解。  
2. 实证：实验一路径控制（N=24）给出听觉结构对导航错误率、纠正率、负荷的系统影响。这是主体证据。  
3. 设计：HierarchyTone 把**预测性**实例化到读屏里，并指出边界——DOM 与语义层级对应时可用，语义与结构解耦时失效（淘宝）；中间层 L3–L5 难分辨。盲审意见第 6 条已点名：N=2 不能当有效性验证，淘宝失效要诚实写。

因此：

- 把手机**边框**拿掉、改成全幅呈现 → 方法细节，不减亮点。现场还能收视障青少年样本，正好补第 8 章证据不足。  
- 把淘宝/头条**换成干净的桌面门户** → 会伤设计章。失效边界没了，只剩「结构清楚的页面上音高有用」，审稿人会觉得你避开了难例，亮点变弱。  

**字段结论：全幅可以，门户化不行。** 正式刺激用拉满窗口的淘宝 + 头条（去金属框、去研究侧栏），保留两套信息架构的对照。新闻偏 DOM–语义对应，购物偏解耦，这才是 HierarchyTone 相对实验一迷宫的独特贡献。

### 4.7 全盲如何不划出测试区？能否用 iPad？

全盲在笔记本上容易「越过边框」，不是因为界面太大，而是**触控板是相对位移**：指针在屏幕上，手指在另一块板上，摸不到框。低视力能用眼睛校正，全盲不能。

**原则：不要让测试区外面存在可点的空白。** 最稳的是手指摸到的那块玻璃 = 全部刺激。

#### 首选：iPad 全屏指读（建议作为实验二主设备）

这和手机读屏是同一套技能（VoiceOver 触探），比笔记本悬停更真，也没有「框外」。

现场做法：

1. Safari 打开原型，或「添加到主屏幕」成独立全屏网页（去掉浏览器地址栏）。  
2. **关掉系统 VoiceOver**。真实 VoiceOver 会抢走触控，插不进自定义音高。本实验用我们自己的：滑过 = 音高+语音，双击 = 激活。  
3. 打开 iOS **引导式访问（Guided Access）**：设置 → 辅助功能 → 引导式访问。三击侧边键锁定在当前 App，可禁止滑出、按主屏、乱点状态栏。必要时圈掉屏幕底部 Home 条，避免误触。  
4. 横屏、屏幕常亮、插耳机。刺激铺满可视区，淘宝/头条结构放大，不要留研究侧栏。  
5. 笔记本只给主试：建档、下一题、导出。iPad 不显示 L1–L6 图例。

网络：iPad 打不开本地 `file://`。用笔记本开一个本地静态服务（或手机热点 + GitHub Pages），iPad 和电脑进同一页。实验开始前点一下屏幕以解锁 Web Audio。

论文方法里写清：实验室用平板全屏呈现手机信息架构，关闭系统读屏，由原型模拟触探；非真实握持 375px 手机。

#### 若必须用笔记本带全盲

按优先级：

| 办法 | 作用 | 备注 |
|------|------|------|
| 刺激铺满整屏，外面没有任何按钮 | 没有「框外」可划进 | 最低要求；触控板仍可能把指针甩到屏幕边缘外，需主试把指针拨回来 |
| 划出刺激区立刻耳标（「已离开界面」）并停播 | 听觉围栏 | 必须做；可加短噪音 |
| 主试把被试手指放到触控板中央再开始 | 定位 | 每题开始口述「手在板子中间」 |
| 触控板上贴一圈胶带/硬纸框，面积对应屏幕 | 可摸到的物理边界 | 便宜、现场有效 |
| 左右滑切换上一项/下一项（TalkBack 单指滑） | 不依赖二维瞄准 | 全盲备用通道，只教这一个手势；与触探不同，日志里记 `input_modality` |

不要为此改回方向键。单指左右滑是手机读屏已有手势，不是电脑快捷键。

#### 视力分组怎么用设备（建议）

- 全盲：iPad 触探为主。  
- 低视力：同一台 iPad 全屏（残余视力也不容易看出界）；或笔记本全幅，但不要小手机框。  
- 实验一迷宫仍用笔记本键盘，两套设备分工，不必把导航实验搬上 iPad。

预实验必须在真机 Safari 上滑一遍：iOS 会把滑动当成滚页，见下节。

#### iPad 触控要怎么开发（现有页不能直接用）

现在的 `实验二.html` 有两处会在 iPad 上失效：

1. 只用 `mouseover`。Safari 不会在手指拖动时连续触发鼠标悬停，所以「检测不到触控变化」。  
2. `.phone-screen { overflow-y: auto }`。系统把滑动解释成滚下一页，焦点层收不到 move。

正确模型是 **Touch/Pointer 事件 + 禁止滚动 + 按坐标命中**，不要指望 hover。

**CSS 锁滚动（刺激容器及其所有子节点）：**

- `html, body { overflow: hidden; position: fixed; inset: 0; touch-action: none; }`
- 实验态禁止任何 `overflow: auto / scroll`
- `overscroll-behavior: none`，viewport：`maximum-scale=1, user-scalable=no, viewport-fit=cover`
- 可加 `apple-mobile-web-app-capable`，让「添加到主屏幕」去掉地址栏

**JS 锁滚动：**

- `touchstart` / `touchmove` 必须 `{ passive: false }`，并 `preventDefault()`。默认 passive 时 preventDefault 无效，页面照样滚。
- 另拦 `gesturestart`（双指缩放）。

**命中（触探核心）：**

手指坐标 → `elementFromPoint(x, y)` → `closest('[data-lv]')`。  
用一层铺满的透明 `#hit` 接所有 touch；命中时先把 overlay 的 `pointer-events` 设为 `none`，取下面的节点，再开回来。节点变了才播音高+语音，同一节点不重播。

**手势（对齐 VoiceOver，仍不教键盘）：**

- 按住滑动 = 触探（对应指哪读哪）
- 400ms 内点两下 = 选中目标
- 第一下点击用于解锁 Web Audio（Safari 强制）

笔记本仍可保留 hover，作为同一套 `explore(node)` 的第二条入口。

仓库里已有探针页 `prototype/ipad-touch-probe.html`：在 iPad Safari 打开，滑动时格子应变色出声，页面不应跟着走。过了这一关，再把同一套输入接到淘宝/头条树上。

## 5. 网页端模拟读屏：做成什么样

网页端的意义是**把指读平面做大**，操作仍是悬停，不是改成电脑读屏快捷键。

两种做法，正式实验只选一种（见 4.5）：

- **A. 放大版 App**：现有淘宝/头条结构拉满窗口，仍是手机信息架构。生态效度更接近「手机读屏」。  
- **B. 桌面门户**：顶栏、类目、栅格/信息流、页脚。探索面最大，低视力最不容易出界；论文口径改成网页/大屏场景。

### 5.1 若走 B（门户），场景仍对齐现有内容

1. **购物门户**（对应淘宝）：顶栏搜索、类目、促销、商品栅格、页脚。全宽，字号 18–22px。  
2. **新闻门户**（对应头条）：站点名、频道、置顶要闻、信息流。  

层级 L1–L6 与现有标注同一套操作定义。门户页**不要**再做 `H` 键跳转作为被试技能。

### 5.2 层级操作定义（论文口径）

| 层级 | 音高 | 门户上典型节点 | App 上典型节点 |
|------|------|----------------|----------------|
| L1 | C5 523Hz | 站点顶栏、主导航、页脚 | 顶栏、Tab Bar |
| L2 | G4 392Hz | 频道、区块标题 | 频道入口、区域标题 |
| L3 | D4 294Hz | 商品卡、新闻条目 | 商品卡、新闻条目 |
| L4 | A3 220Hz | 标题文字 | 标题文字 |
| L5 | E3 165Hz | 图片、来源/价格元数据 | 图片、元数据 |
| L6 | B2 123Hz | 深层附加信息 | 深层嵌套 |

### 5.3 网页端视觉（给低视力）

- 默认大字、高对比、当前焦点有清晰描边（约 4px），随指针移动。  
- **不要**在被试模式显示 L1–L6 色标。  
- 可选高对比主题，记入日志。

### 5.4 为什么不直接用真实读屏软件

现场若开 TalkBack/NVDA，无法稳定插入自定义音高。本原型模拟「指哪读哪 + HierarchyTone」，不是替换永德/NVDA。说明稿写清即可。

## 6. 规范后的实验流程

### 6.1 整天节奏（与盲校方案对齐，单人 60–90 分钟）

```
建档 3 min
  → 实验一 听觉导航 35–50 min（含 TLX）
  → 休息 5 min
  → 实验二 HierarchyTone 20–30 min
  → 致谢
```

实验二内部必须再拆成可重复的试次，不能再是「自由点十分钟再聊天」。

### 6.2 实验二试次结构（建议，可在预实验后微调）

**自变量（被试内）：**

- C0 基线：仅语音，无层级音高  
- C1 HierarchyTone：音高 + 语音  

这是论文要回答的：音高层级是否帮得上忙。现在的原型只有 C1，没有对照。

**刺激面（选一种，贯穿正式题，不当自变量）：**

- 推荐现场：网页全幅（或拉满窗口的 App 页），悬停指读。  
- 手机小框不作为正式条件。演示模式可保留原 375px 外观。

**场景：** 购物 1 题 + 新闻 1 题，平衡熟悉度，不当第二个自变量。

**建议正式矩阵（控制在约 20 分钟）：**

| 顺序 | 内容 | 时长 |
|------|------|------|
| 0 | 音高辨别校准：依次播 L1–L6，口头确认能否分出高低 | 2 min |
| 1 | 练习：无关小页，C1，不记成绩 | 2 min |
| 2 | 正式：场景 A × C0 或 C1（顺序拉丁方） | 3–4 min |
| 3 | 正式：同一场景 × 另一条件 | 3–4 min |
| 4 | 正式：场景 B × 先做的条件 | 3–4 min |
| 5 | 正式：场景 B × 另一条件 | 3–4 min |
| 6 | 口头问卷（主试勾选） | 8–10 min |

4 个正式试次 × 2 条件，足够做被试内比较，又压得住现场时间。刺激面全场一致，不要中途换手机/网页。

**顺序平衡：** 偶数编号 C0→C1，奇数编号 C1→C0；场景 A/B 对半交换。写进 `protocol.js` 自动分配，主试不手选。

### 6.3 任务必须是「找得到对错」的，不是闲逛

每题一个目标、一个正确答案、一个超时（建议 90s）。

示例（开发时把目标节点 id 写死）：

- 购物：找到「购物车」并单击  
- 购物：找到标价 59 元的秒杀商品标题并单击  
- 新闻：找到置顶要闻标题并单击  
- 新闻：找到体育相关那条新闻标题并单击  

成功：指针停在目标上并单击。  
失败：超时、或点了错误目标（记一次 error，可允许继续找，直到超时或成功）。  
主试可 `Esc` 标「中止」，不当错误。

### 6.4 练习与指导语（现场口述，系统可播一遍）

要点：

1. 声音先响一声，再说话；高音更浅、低音更深。  
2. 把手放到触控板/鼠标上，在页面上慢慢划，指到哪读哪；听到目标就点一下。  
3. 没有时间压力表演，找不到可以说「过」。  

不要教方向键或标题跳转。C0 指导语删掉「先听音高」一句。

### 6.5 问卷（口头，主试代填）

系统在全部试次结束后弹出主试表（大控件，可键盘）。建议题项固定，便于和开发字段对齐：

1. 音高能否分辨出至少「高 / 中 / 低」三档  
2. 音高是否帮你判断「在哪一层」  
3. 有音高 vs 无音高，哪次更好找  
4. 与常用读屏相比，最不习惯的一点  
5. （仅当练习里展示过小框手机时）大界面是否比小框更好划  
6. SUS 或 UMUX-Lite 四项口译（可选）  
7. 开放：改进建议  

量表 1–5，主试读题、被试说数字。开放题可录音，系统只留摘要文本框。

实验二**不必每题都上 NASA-TLX**（实验一已经很重）。若要负荷，只在 C0/C1 全部结束后各评一次极简 3 项（努力、挫败、绩效）。

## 7. 数据记录（上场必须能导出）

每个正式试次一条 `trial`，悬停进入/离开/点击都记 `event`。本地 `localStorage` 自动存，结束下载 JSON + CSV。

### 7.1 session

```
participant_id, vision (blind|low_vision), sr_exp (none|some|daily),
device_habit (phone|computer|both), surface (web_full|phone_enlarged),
contrast_theme, order_code, started_at
```

### 7.2 trial

```
trial_id, scene (shop|news), surface, condition (C0|C1),
task_id, target_node_id, success (0|1), timeout (0|1), aborted (0|1),
time_ms, n_focus_enters, n_errors, unique_levels_visited
```

### 7.3 event

```
t_ms, type (enter_node|leave_node|activate|interrupt|error|success),
node_id, level, speech_text
```

分析最小集：成功率、完成时间、进入节点次数、错误点击。路径可事后画。不要只存「触发总次数」那种演示统计。

## 8. 文件与模块怎么拆

现有两个巨型 HTML 先保留作备份（改名 `实验二.demo.html`），新代码按模块切，仍然可打成少量 HTML 入口，方便现场。

```
prototype/
  session.html                 统一入口：建档、选实验一/二、导出
  exp1/

    css/
```

## 9. 开发分期（可行、可停）

### 第 0 期 — 冻结口径（0.5 天）

- 确认：C0/C1 被试内；悬停为正式输入。  
- 确认刺激面：全幅网页 **或** 拉满窗口的 App 页（二选一，正式题不混用）。  
- 确认：4 正式试次 + 校准 + 练习。  
- 把任务目标句和节点 id 写进 `tasks.json` 草稿。

### 第 1 期 — 共享内核（2–3 天）

- `tree.js` + `audio.js` + 悬停命中（最深节点、去抖），十个节点先跑通。  
- 单击激活、离开刺激区停播、C0/C1 开关。  
- 无主试 UI 也能本地验证。

### 第 2 期 — 正式刺激面（2 天）

- 按第 0 期选择：门户全幅，或现有淘宝/头条拉满去边框。  
- 大焦点描边、隐藏层级色标、两侧无研究面板。

### 第 3 期 — 演示用小框（0.5–1 天，可后置）

- 旧 375px 三栏仅用于讲解/答辩，不进正式试次。

### 第 4 期 — 实验状态机（2 天）

- 建档、拉丁方、练习/正式、90s 超时、成功/失败语音。  
- 主试浮层：当前题、条件、强制下一题、中止。  
- logger 导出；问卷页。

### 第 5 期 — 会话壳与现场打磨（1–2 天）

- `session.html` 串实验一 PID。  
- 自己用耳机走完全程；再找 1 名同事蒙眼预实验。  
- 更新盲校方案表述，与选定刺激面一致。

合计大约 **7–11 个工作日**。不要把真实 TalkBack/NVDA 桥、每人两套外壳做到第一版。

## 10. 验收标准（做完可以上场的最低线）

1. 不插网，Chrome/Edge 打开 `session.html` 能跑完实验二。  
2. 只靠划过 + 单击能完成全部正式题；被试模式看不到 L1–L6 图例。  
3. 14 寸笔记本上刺激区占满工作区，划到边缘不会点到研究控件。  
4. 同一任务在 C0/C1 下节点完全一致，只差有无音高。  
5. 导出 CSV 含 pid、condition、scene、surface、success、time_ms、n_focus_enters。  
6. 主试能在不看代码的情况下按口述稿带完一名被试。

## 11. 风险与现场对策

| 风险 | 对策 |
|------|------|
| `speechSynthesis` 中文音色差或卡住 | 实验二已有 pause/resume 保活；现场只装 Edge；预备离线 wav 播报方案作第 2 期后备份 |
| 低视力仍划出刺激区 | 实验模式无框外控件；刺激面拉满窗口 |
| 全盲用触控板找不到页面 | 主试把指针放到页面中央再开始；练习 1 分钟；不改成记键 |
| 时间不够 4 试次 | 协议允许降级：每场景只做 1 条件（变成被试间），日志里 `protocol_version` 标明 |
| 音高与语音掩蔽 | 保持「音高先、语音后」；校准阶段确认能分开 |
| 伦理：界面像真淘宝/头条 | 页眉标明「实验模拟页」；数据为虚构 |

## 12. 需要你拍板的 4 件事（写代码前）

1. **对照条件 C0**：是否做「仅语音」对照？强烈建议做，否则现场数据很难写进论文结果。  
2. **每人体量**：默认 4 正式试次（2 场景 × 2 条件）。若盲校单人只能再给 15 分钟，改为 2 试次。  
3. **刺激面二选一**：全幅网页门户，还是把现有手机页拉满窗口（去边框）。正式题不要两套都做。  
4. **技术**：继续静态 HTML（推荐）还是愿意上打包工具？

这 4 条不定，第 4 期状态机的任务表写不死。悬停作为正式输入已按你的意见冻结，不再列为待定。
